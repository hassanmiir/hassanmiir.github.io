The Big Idea

An expression is a question the computer answers

You write a small sum; C++ works it out and hands back one value.

int total = 80 + 60;      // expression on the right → 140
double avg = total / 2.0;   // another expression → 70.0

An operator (+, /…) combines operands (the values) into a result.

80 + 60 → [ 140 ]

Hold onWhat does 7 / 2 give? Not 3.5, if both numbers are int. That trap is the next slide.
The Division Trap

Two whole numbers divide to a whole number

7 / 2        // → 3    (not 3.5! the .5 is dropped)
7.0 / 2      // → 3.5  (one decimal makes it a real divide)
7 / 2.0      // → 3.5
(double)7/2  // → 3.5  (force it)

int ÷ int = int

C++ throws away the fraction. 7/2 is 3, 1/2 is 0.

The fix

Make one side a decimal: / 2.0. Now you keep the decimals.

Why it mattersAn average of marks with / 2 silently loses accuracy. Grades must use / 2.0.
New Operator

Modulo % — the leftover

% gives what's left over after dividing whole numbers.

17 / 5   // → 3   (how many fit)
17 % 5   // → 2   (what's left over)

Even or odd?

n % 2 == 0 → even. The classic use.

Split into groups

30 students, groups of 4 → 30 % 4 = 2 left over.

Pens down when you have all six. Then we check — and run it.

The Answer

Check your six

13 / 4 = 3 13 % 4 = 1 (4×3 + 1 = 13)
20 / 5 = 4 20 % 5 = 0 (divides evenly)
7 / 10 = 0 7 % 10 = 7 (10 doesn't fit — all 7 left over)
The surprising one7 / 10 = 0 catches everyone. Fewer than one "10" fits, so the whole-number quotient is 0 and the remainder is the lot.

The #1 beginner bug= puts a value in a box. == asks a question. mark == 50 checks; mark = 50 overwrites!
Combine Conditions

and &&, or ||, not !

&& — both must be true

mark >= 50 && attended → passed and showed up.

|| — at least one is true

isStaff || isAdmin → either one grants access.

! — flips it

!isOpen → true when it's closed.

These build the pass/fail rule you'll use in Lecture 4.

Work It Out On paper · 2 min

True or false? Work each one out

Take mark = 72, attended = true, isStaff = false. Write T or F for each.

mark >= 50 ?
mark >= 50 && attended ?
mark > 90 || isStaff ?
!attended ?
Reason it step by step — evaluate each side, then combine.
Silence, pens moving. The tricky one is row 3: mark>90 is false, isStaff is false, OR of two falses is false. Row 4: attended is true, so !attended is false. Ask the room to vote T/F per row before revealing.
The Answer

How each one resolves

mark >= 50 true 72 ≥ 50 ✓
mark >= 50 && attended true true AND true
mark > 90 || isStaff false false OR false — needs one true
!attended false attended is true, ! flips it
That's the pass ruleRow 2 is exactly the condition your program builds next — a bool straight from the operators you just evaluated.

PART 3

Order of operations

Which part runs first — and how brackets put you in control.

× and ÷ before + and −
Brackets always win
The Rule

C++ follows the maths order you know

2 + 3 * 4        // → 14, not 20  (× first)
(2 + 3) * 4      // → 20          (brackets first)
80 + 60 / 2      // → 110, not 70 (÷ first!)
(80 + 60) / 2    // → 70          (what you meant)

% ranks with * and /; comparisons and &&/|| come after the arithmetic.

When in doubt, bracket

Extra ( ) never hurt — they make your intent obvious and bug-proof.

The average bug

a + b / 2 only halves b. You need (a + b) / 2.0.

Work It Out On paper · 2 min

This average is wrong. Fix it.

A student scored 80 and 60. This line should give 70.0 — but it doesn't.

double avg = 80 + 60 / 2;
1 · What does this actually compute? ?
2 · Rewrite it so it gives 70.0
Two things are wrong — the order and the decimals. Find both.
Let them struggle. Hint only if stuck: "which runs first, + or / ?" The bug: 60/2 runs first = 30, then 80+30 = 110. And even bracketed, (80+60)/2 is int/int = 70 by luck here but / 2.0 is the safe habit. Reveal next.
The Answer

Two bugs, one line

// WRONG — / runs before +, so:
80 + 60 / 2   // = 80 + 30 = 110  ✗

// RIGHT — bracket the sum, keep decimals:
(80 + 60) / 2.0   // = 140 / 2.0 = 70.0  ✓

Bug 1 — order

/ beats +, so only 60 got halved. Brackets fix it.

Bug 2 — decimals

/ 2.0 keeps the fraction, so averages never silently round.

The weighted grade

A course grade is 40% coursework + 60% exam. Compute it and decide pass/fail:

  1. Read coursework and exam marks (0–100).
  2. Weight them: final = cw*0.4 + exam*0.6 — watch the decimals!
  3. Decide: a bool passed — is final >= 50?
  4. Print the final mark and whether they passed.
The catchUse 0.4 and 0.6 (decimals) so the weighting isn't rounded to zero — the division trap, again in disguise.
Work It Out First On paper · 3 min

Predict the result before you write a line

Coursework = 70, exam = 40, rule = 40% + 60%, pass = >= 50. Work it out by hand.

1 · coursework × 0.4 = ?
2 · exam × 0.6 = ?
3 · final mark (add them) = ?
4 · passed? (final ≥ 50) = ?
Agree your four answers in your pair. Then code it — and check the machine matches your paper.
This is the key one for understanding: they compute the expected output BY HAND, then write code to confirm. When the program prints what their paper said, the operators click. Answer: 28, 24, 52.0, passed = true.

One Solution Compare yours

How the calculator works

double final = coursework * 0.4 + exam * 0.6;  // decimals keep accuracy
bool passed = final >= 50;

cout << "==== GRADE ====" << endl;
cout << "Coursework: " << coursework << endl;
cout << "Exam:       " << exam << endl;
cout << "Final:      " << final << endl;
cout << "Passed:     " << passed << endl;
cout << "===============" << endl;

Weighting = multiply + add

70·0.4 + 40·0.6 = 28 + 24 = 52.0.

final >= 50 → true

A comparison gives the pass bool — no "if" needed yet.

That's a gradebook row
