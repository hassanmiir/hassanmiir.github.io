Lecture 6 · Functions

Write it once.
Use it forever

Copy-paste the same ten lines everywhere you need them, then fix the bug in all ten places? Never.
Wrap them in a function — name it once, call it by that name anywhere, fix it in one spot.

A 2-hour hands-on session · you'll build your own reusable tools

Hook: a function is a NAME for a block of code. Like 'cout' and 'sqrt' already are — today they write their own. The payoff: write/fix in one place, reuse everywhere.
Where We Left Off

Loops repeat lines in one place

A loop runs the same lines again and again — but only right there, where you wrote them. What if you need that same job in five different places?

Give the job a name. Then you can run it from anywhere just by writing the name. That named block is a function.

name it → call it → reuse it

You've Used These Since Day One

Functions aren't new — you just never wrote one

main()

Every program is one big function. The computer calls it to start.

sqrt(16)

You hand it 16, it hands back 4. You never see how — you just use the name.

getline(...)

Someone wrote it once. Millions of programs call it. That's the whole point.

The mental modelA function is a machine: something goes in, a result comes out, and you don't need to see the gears to use it.
PART 1

The machine

What goes in, what comes out, and how to build one.

Inputs (parameters)
Output (return value)
Build & call one — live
The Shape

Four parts — name, inputs, body, result

int square(int n) {     // name: square, input: one int
    return n * n;       // hand the result back
}

int main() {
    cout << square(5);  // call it → prints 25
}

square(5) becomes 25 — the call is replaced by whatever it returns.

int square — return type + name

int = the kind of answer it gives back. square = how you call it.

(int n) — parameter

The input slot. When called with 5, n becomes 5 inside.

return n * n — the result

Computes the answer and sends it back to whoever called.

Watch It Run Plays automatically

See a function call and return

Watch control jump up into square, the parameter receive a copy of 5, the result come back as 25 — and main carry on.

The big idea to narrate: control LEAVES main, runs the function, then RETURNS to exactly where it left off, carrying a value. Pause on 'return a value' — that 25 flows back into the call site. Students replay on their screens.
You Be the Computer On paper · 3 min

Trace it — what does main print?

Follow the calls by hand. Each call becomes its returned value. Write the final line of output.

int twice(int x) {
    return x + x;
}
int main() {
    int a = twice(3);
    int b = twice(a);
    cout << a << " " << b;
}
twice(3) = ?
a = ?
twice(a) = ?
Output: ? ?
Do the first call, write down a, THEN feed a into the second call.
Silence, pens moving. twice(3)=6 so a=6. twice(a)=twice(6)=12 so b=12. Output: 6 12. The trap: students try to feed 3 into the second call — no, it's 'a', which is already 6. Reveal next.
The Answer

Output: 6 12

twice(3) → 3+3 = 6 a = 6 twice(6) → 6+6 = 12 prints 6 12
The trickThe second call uses a, not 3. By then a is already 6, so you're really calling twice(6). A function always works on the value it's actually given — right now.

PART 2

return vs void

Some functions hand back a value. Some just do a job.

return — give an answer
void — just do it
many parameters
Two Kinds of Function

return gives an answer · void does a job

int add(int a, int b) {     // two parameters
    return a + b;           // gives a number back
}

void banner(string t) {     // returns nothing
    cout << "=== " << t << " ===";
}

int main() {
    int s = add(4, 9);      // s = 13  (capture the answer)
    banner("Report");       // just prints — nothing to capture
}

Returns a value

Use it like a number: store it, print it, add it. int s = add(4,9).

void — no value

It acts (prints, saves) but there's nothing to catch. Just call it.

Many inputs

Separate parameters with commas: add(int a, int b). Order matters.

Quick Check Think!

What's wrong with this function?

int biggest(int a, int b) {
    if (a > b)
        cout << a;
}

It says it returns an int…

A The name is too long
B It prints instead of returning — and misses a case
C It can't take two inputs
Two bugs: (1) it promises 'int' but never returns anything; (2) even the logic only handles a>b. A function that declares a return type MUST return a value on every path. Fix: return a; else return b;.
Your Turn · Live Code Run it!

Reuse one function many times

One maxOf function, called three times on different numbers. Change the numbers and run again. (Input: none)

#include <iostream> using namespace std; int maxOf(int a, int b) { if (a > b) return a; return b; // reached only when a is not bigger } int main() { cout << maxOf(3, 9) << endl; cout << maxOf(20, 7) << endl; cout << maxOf(5, 5) << endl; return 0; }
Note how 'return a' ends the function immediately — if it runs, 'return b' never does. Three calls, one definition. 9, 20, 5. This is the pattern they'll extend in the challenge.
PART 3

Scope & the copy trap

Why the variable inside a function is in its own little world.

Local variables
Arguments are copies
The Classic Trap

Changing a parameter doesn't change the original

void tryToChange(int x) {
    x = 999;            // changes only the COPY inside
}

int main() {
    int score = 10;
    tryToChange(score);
    cout << score;      // still 10 — not 999!
}

It's a copy

When you call tryToChange(score), x gets a copy of 10. Changing x never touches score.

The fix

Want the new value? Return it and assign: score = bump(score);

Remember from the animationThe parameter n received a copy of 5. Same rule here — inside a function you work on copies, and send results back with return.
You Be the Computer On paper · 3 min

Predict the output

Two variables are both called n — one inside, one in main. They are not the same box.

int addTen(int n) {
    n = n + 10;
    return n;
}
int main() {
    int n = 5;
    int r = addTen(n);
    cout << n << " " << r;
}
n inside addTen becomes ?
r = ?
n in main is still ?
Output: ? ?
The n inside is a copy. main's n never changes — only r catches the result.
Inside: n becomes 15, returned. r = 15. main's own n is still 5 (it was only copied in). Output: 5 15. The trap: students expect '15 15'. Drive home local scope. Reveal next.
The Answer

Output: 5 15

copy 5 into addTen's n n → 15, returned r = 15 main's n untouched → 5
Local means localA variable born inside a function lives and dies there. The only thing that escapes is what you return. That's why we captured it in r.

One Solution Compare yours

How it works

char grade(int score) {
    if (score >= 90) return 'A';
    if (score >= 80) return 'B';   // checked only if not 90+
    if (score >= 70) return 'C';
    return 'F';                    // the catch-all
}

bool passed(int score) {
    return grade(score) != 'F';    // reuse grade — don't repeat the rule!
}

return ends it

The first true if returns and stops — so order matters: highest first.

Functions call functions

passed leans on grade — the rule lives in one place only.

bool result

A function can return a yes/no (true/false) just as easily as a number.
