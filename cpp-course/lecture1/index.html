Part 1

What is programming, really?

Let's build the idea from the ground up.

The Big Idea

A program is a set of instructions

A program tells a computer exactly what to do — step by step, in order.

Everyday analogyA recipe is a program: "Add flour, then stir, then bake 20 min." The cook follows each step in order.

The computer is fast and obedient — but it does exactly what you say, not what you meant.

The Big Idea

Why a language?

Computers don't understand English. A programming language is a precise way to write instructions a machine can follow.

You write

Human-readable code, in C++.

Compiler translates

Into instructions the machine runs.

Computer runs

Executes them, step by step.

From Code To Running

Three steps, every time

1 · Write

2 · Compile

Part 2

Your first C++ program

Here it is — five lines. Then we take it apart.

Your First Program

"Hello, World!"

hello.cpp
#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
When you run thisthe computer prints Hello, World! on the screen. Let's understand every piece.
Anatomy · 1 of 4

The #include line

#include <iostream>

This loads a library — ready-made code. iostream gives us input and output tools (the "io").

Like saying: "I'll use the screen and keyboard, so load those tools first."
Anatomy · 2 of 4

The main function

int main() {
    // your instructions go here
}

Every program starts at main — the front door. The braces { } hold everything it does.

Anatomy · 3 of 4

Printing with cout

std::cout << "Hello, World!" << std::endl;

std::cout

The output stream — the screen.

<<

Sends what's on the right into cout.

std::endl

Ends the line (newline after).

Anatomy · 4 of 4

Two vital small rules

return 0; means "finished successfully"

Tells the system the program ended with no errors.

Every statement ends with ;

The semicolon is how C++ knows one instruction has finished. Forgetting it is the #1 beginner slip.

Your Turn · Live Code Run it!

Run your first program

Click ▶ Run. Then change the words inside the quotes and run again.

#include <iostream> using namespace std; int main() { cout << "Hello, World!" << endl; return 0; }
Give them 3–4 minutes. Walk around. Encourage changing the text and re-running. Note we added "using namespace std;" so they can write cout instead of std::cout — mention it briefly.
Did You Notice?

A small shortcut: using namespace std;

In the live box we wrote cout, not std::cout. The line using namespace std; lets us drop the std:: prefix.

For beginnersWe'll use this shortcut in class to keep code short. Both styles are correct.
Predict the Output Think first!

What does this print?

cout << "C" << "+" << "+";
cout << " is fun";
A C + + is fun (with spaces)
B C++ is fun
C C++ (newline) is fun
Let them vote by hand first, then tap. Key teaching point: cout joins pieces exactly, and only endl / "\n" makes a new line.
Part 3

Mastering output

You control exactly what appears on screen.

Output

Chaining with <<

cout << "Hello" << ", " << "World" << "!" << endl;

Send several pieces in one line. They print left to right, joined together.

PrintsHello, World!
Output

New lines & special characters

endl

Move to a new line.

\n

Also a new line, inside quotes.

\t

Insert a tab space.

cout << "Line one\nLine two\tTabbed" << endl;
Your Turn · Live Code Experiment

Make it print your way

Run it. Then try: add a \n, add a \t, print three lines about yourself.

#include <iostream> using namespace std; int main() { cout << "My name is ____" << endl; cout << "I am learning C++" << endl; cout << "Today I wrote my first program!" << endl; return 0; }
Readability

Leaving notes: comments

// A single-line comment — the computer ignores it
cout << "Hi"; // comments can sit after code too

/* A multi-line
   comment */

Comments are for humans. The compiler skips them. Use them to explain why.

Part 4

Talking to the user

Programs get more fun when they listen and respond.

Input

Reading input with cin

char name[40];
cout << "What is your name? ";
cin >> name;
cout << "Hello, " << name << "!";

cin >>

Reads what the user types into a variable.

The arrows flip

cout << sends out · cin >> brings in.

We use char name[40] here (a text buffer) because it runs in the in-slide compiler. In Lecture 2 we introduce std::string properly. Don't dwell on the difference.
Your Turn · Live Code Interactive

Greet the user by name

The input box is pre-filled with a sample name. Run it — then change the greeting and run again.

#include <iostream> using namespace std; int main() { char name[40]; cout << "What is your name? "; cin >> name; cout << "Welcome, " << name << "!" << endl; return 0; }
Explain: the stdin ("Ana") simulates the user typing, since slides can't pause for keyboard input. On a real compiler they'd type it themselves. Encourage changing "Ana" is not possible here, but they can change the greeting text.
Mini Challenge 5 min

Add a second question

The program reads a name and a favorite number. Make it also print the number doubled. (Hint: num * 2)

#include <iostream> using namespace std; int main() { char name[40]; int num; cout << "Name and a number: "; cin >> name >> num; cout << "Hi " << name << ", your number is " << num << endl; // TODO: print num doubled return 0; }
Solution: add cout << "Doubled: " << num*2 << endl; Walk around and help. This previews variables + arithmetic (Lectures 2–3) in a gentle way.
Part 5

Errors are your friends

Let's make some on purpose.

Debugging Early

Three errors you will meet

Missing ;

"expected ';'" — add the semicolon.

Mismatched { }

Every opening brace needs a closing one.

Typo in a name

cot instead of cout.

Your Turn · Break It! Experiment

Cause an error on purpose

Run it (works). Now delete the semicolon after the first line and run again. Read the error. Then put it back.

#include <iostream> using namespace std; int main() { cout << "This line works" << endl; cout << "So does this one" << endl; return 0; }
The lessonNow you've seen that error once — you'll recognize it forever.
Mindset

How real programmers debug

Read the message

It usually names the line and the problem.

Fix one thing, run again

Small steps beat big guesses.

Repeat calmly

Every bug you fix makes you faster.
